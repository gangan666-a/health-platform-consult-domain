## 1. 项目背景

### 1.1 平台全景

「医疗买药问诊平台」连接**患者、医生、药师**三方：用户身体不适或需要购药时，从导购咨询出发，必要时进入在线问诊，由医生开具处方、药师审核处方，最终凭处方完成购药。平台按业务边界划分为四大领域，各自独立工程：

| 领域 | 职责一句话 |
| --- | --- |
| 商品领域 | 非药品类商品的目录、库存与价格 |
| 导购领域 | 用户意图理解、用药咨询引导，把「想买药」转化为「需要问诊」的线索 |
| **问诊领域（本工程）** | 从接诊到开方的完整医疗服务闭环 |
| 订单领域 | 购药订单、支付与履约 |

**上下游关系**：问诊领域上游是导购领域（接收问诊线索：用户 + 主诉 + 意向药品），下游是订单领域（输出处方凭据：处方号 + 状态 + 药品明细快照）。

### 1.2 本工程定位

- **主体**：`agent-service` 多 Agent 智能体（Manager + 6 Sub Agent 编排、RAG、报告解读）——问诊领域的用户侧统一入口。
- **核心链路服务（领域直接负责）**：分配医生 → 问诊记录 → 开处方 → 分配药师（审方）。
- **支撑服务（2B 管理）**：医生药师管理、排班、药品服务、工资结算、处方管理。
- **存量实现**：`consult-service`（问诊会话/IM/开方参考实现）、`medicine-service`（药品目录）已可用，将被新架构逐步拆分收敛。
- **本期范围**：完成领域建模与服务拆分（文件夹 + 实现要求），服务实现与前后端代码**不在本期**。

## 2. 目标用户

| 用户类型 | 描述 | 主要诉求 |
| --- | --- | --- |
| **患者（核心用户）** | 需要用药咨询或处方的购药用户 | 快速匹配医生、流畅问诊沟通、合规拿到处方 |
| **医生** | 平台入驻的执业医师 | 高效接诊、便捷开方、收入透明可结算 |
| **药师** | 平台入驻的执业药师 | 及时收到审方任务、审方留痕可追溯 |
| **平台运营（2B）** | 管理医护人员、排班与结算 | 人员资质合规、排班可控、结算准确 |
| **研发 / 测试（系统用户）** | 开发与质量保障人员 | 明确可测试的需求边界、异常行为、验收标准 |

## 3. 项目目标

1. **G1 · 问诊核心链路闭环**：患者线索 → 分配医生 → 在线问诊（全程留痕）→ 医生开方 → 分配药师审方 → 处方生效，全链路状态可追溯。
2. **G2 · 医疗合规底线**：无执业资质不上岗、处方药必须凭生效处方购买、处方一次性消费、审方意见留痕不可改。
3. **G3 · 2B 管理闭环**：医护人员档案与排班数字化，接诊/审方/处方/出勤口径的工资结算准确可对账。
4. **G4 · 领域边界清晰**：对上游导购只收「问诊线索」，对下游订单只出「处方凭据」，不越界实现其他领域。

## 5. 功能需求（服务级，FR 明细由 /sdd 逐个展开）

> 每个服务的**模块约束、必守规则、验收口径**见 `harness/agents/<service>.md`；此处只列边界与责任。

| 编号 | 服务 | 需求要点 | 状态 |
| --- | --- | --- | --- |
| FR-1 | doctor-assignment-service 分配医生 | 问诊请求按「科室 → 排班在线 → 负载」调度给医生；排队 FIFO + 紧急插队 + 超时转派；线索不完整拒收 | 🚧 占位 |
| FR-2 | consult-record-service 问诊记录 | 问诊全过程事件 append-only 留痕；会话回放、用户历史、归档取证 | 🚧 占位 |
| FR-3 | prescription-service 开处方 | 医生在线开方（诊断 + Rx 药品明细 + 用法用量）；资质/接诊/药品三重前置校验 fail-closed | 🚧 占位 |
| FR-4 | pharmacist-assignment-service 分配药师 | 处方审方环节的药师调度；资质 + 在线 + 负载过滤；审方时效统计 | 🚧 占位 |
| FR-5 | prescription-management-service 处方管理 | 处方全生命周期状态机（开立→审方→生效→消费/驳回/过期）；审方留痕；对下游订单输出凭据 | 🚧 占位 |
| FR-6 | staff-management-service 医生药师管理 | 医护档案、执业资质、入驻审核、在职状态生命周期；无资质不上岗 | 🚧 占位 |
| FR-7 | scheduling-service 排班 | 班次模板、周期排班、可约容量、调班停诊；「谁在线可调度」唯一事实源 | 🚧 占位 |
| FR-8 | medicine-service 药品服务 | 药品目录（Rx/OTC）、详情、原子库存扣减/回补 | ✅ 已实现 |
| FR-9 | salary-service 工资结算 | 接诊/审方/处方/出勤计费；周期结算幂等、金额精确、结算单状态机 | 🚧 占位 |
| FR-10 | agent-service 多 Agent 智能体 | 用户侧统一入口：意图理解、问药咨询、报告解读、问诊线索汇入 | ✅ 已实现 |
| FR-11 | consult-service 问诊会话（存量） | 问诊会话/IM/开方存量实现，向目标架构渐进拆分 | ✅ 已实现 |

## 6. 关键业务规则（跨服务红线）

| 编号 | 规则 |
| --- | --- |
| BR-1 | 处方药（`rxFlag=true`）购买必须凭**生效处方**；处方一次性消费（CAS），仅「被该订单消费」可回补 |
| BR-2 | 医生开方前必须：在职有执业资质（staff）＋ 已接诊该会话（consult）＋ 药品为 Rx（medicine） |
| BR-3 | 问诊记录 append-only，任何端点不得提供修改/删除入口 |
| BR-4 | 上游线索缺失主诉/用户信息 → 拒收（fail-closed），不猜测补全 |
| BR-5 | 金额全程 `BigDecimal`（2 位小数）；统计源不可用不出账 |
