# PRD 质量门禁（转化前校验）

> Stage 2 使用。**任一「必过」项不过 → 不进入转化**，产出 PRD 质量报告并回产品补齐。对齐范式：`harness-tool-system`（先校验后执行）+ `harness-safety`（fail-closed：歧义即 OPEN，不猜测）。

## 使用方法

逐项核对输入 PRD。每项标注 `✅ 通过 / ⚠️ 缺口`，并给出**证据位置**（`01-PRD.md §8 FR-2`）。必过项出现缺口时，报告状态为 `不通过`，并列出需产品补齐的最小清单。

## 必过项（Blocking）

| # | 门禁 | 判定标准 | 证据要求 |
| --- | --- | --- | --- |
| B-1 | 每个 FR 都有需求描述 | FR-x 有「需求描述」段 | 列出全部 FR 及其状态 |
| B-2 | 每个 FR ≥ 1 个 AC | AC 段有 `AC-FR?-*` 条目 | 列出 FR→AC 计数 |
| B-3 | 每个 AC 可执行 | 写成 Given-When-Then，含具体数值/状态/文案 | 抽查 AC-FR2-3 等 |
| B-4 | 目标可量化 | 每个目标 G1..Gn 有对应指标 M1..Mn + 目标值 | 列出 G↔M 对照 |
| B-5 | 术语已定义 | 术语表覆盖正文出现的业务术语 | 列出未定义术语 |
| B-6 | 异常有期望行为 | 每个 EX 有「期望行为」段 | 列出 EX 计数 |
| B-7 | 非目标明确 | 有 Non-Goals 清单，排除 scope creep | 列出 NG 项 |
| B-8 | 无未决歧义 | 不命中歧义探测器词库，或命中项已有明确裁定 | 列出歧义项 → OPEN |

## 非必过项（Should，缺口降级处理）

| # | 门禁 | 说明 |
| --- | --- | --- |
| S-1 | NFR 有验收要点 | 缺则转化时以「研发推导」补全并标注 derived |
| S-2 | 主流程步骤编号清晰 | 缺则转化时按 FR 描述重排为 P-x，标注 ref |
| S-3 | 用户角色/权限已描述 | 缺则转化时以「匿名单用户」默认并标注 derived |
| S-4 | 现状差异已标注 | 缺则转化时对照代码现状核对，差异入 OPEN |

## 报告输出格式

```
PRD 质量报告：<文档路径> v<版本>
状态：✅ 通过 / ⚠️ 不通过
必过项：8/8 通过（未通过：B-x <原因>）
缺口清单：
  - [ ] B-x：<证据位置> <问题> → <最小补齐要求>
OPEN 待澄清：
  - OPEN-1：<来源> <歧义> <需产品拍板>
建议：<是否可进入 Stage 3>
```
